文档里的参数在本机不被识别时，应先核对三件事：本机是否为文档所针对的 Clash Verge Rev 版本与平台；该参数属于内核配置、Merge 或 Script 增强，还是应用自身设置；当前标签的发布说明是否刚改过相关路径。仓库与发布页是核对依据，未标明版本的转载文档不能单独作为“参数写错了”的结论来源。

## 适用条件

适用：电脑端已安装 Clash Verge Rev；文档给出了具体参数名或字段；本机加载或保存后出现不识别、被丢弃或行为与文档不符。不适用：未安装对应平台安装包；把其他 Clash 图形界面的字段名套用过来；仅凭旧字段记忆判断当前文本失效。

判断“不识别”需要同时看文本与发布说明。发布说明中出现过：扩展配置或脚本写入由应用设置接管的字段时，该值会被丢弃并记录；DNS 覆写中空内容、空字段、Merge 或 Script 覆盖、订阅与规则集缓存路径冲突等，都会让文档里的写法在本机表现为没有生效或被改掉。Windows 不再支持 Win7，该环境下的“不识别”应先视为平台不适用。

## 按版本与平台核对参数是否仍存在

在 https://github.com/clash-verge-rev/clash-verge-rev 确认项目是 Clash Verge 的延续、基于 Tauri 的 Clash Meta 图形界面，功能范围包括 Merge、Script、系统代理、TUN、可视化编辑、WebDav。文档参数若明显不属于该范围，或只存在于已废弃发行通道，本机应判定为不适用，而不是配置拼写错误。

打开 https://github.com/clash-verge-rev/clash-verge-rev/releases ，用本机安装包文件名中的版本（例如 2.5.7）对齐标签名。逐条阅读该标签及相邻标签的修复说明，查找与参数同名的主题：DNS 覆写、Merge、Script、订阅、规则集合、服务模式、TUN。

核对平台分段。Windows、macOS、Linux 在同一版本中修复的问题不同。文档若来自某一系统的服务或 TUN 步骤，本机是另一系统时，参数无效可能是平台前提不成立。Windows 安装包还分普通版本与 `fixed_webview2` 变体，变体用错可能导致应用无法按文档方式运行，从而被误判为参数错误。macOS 需 11+，并区分 Apple M 与 Intel 安装包；Linux 需区分 deb、rpm 与 amd64、arm64、armhf。

核对发行通道。Stable 适合日常使用；Alpha 已废弃；AutoBuild 可能存在缺陷。文档若未声明通道，本机应以 Stable 的字段行为为准。判断依据：本机标签、架构、系统、安装包变体与文档一致，且发布说明未宣布该字段改由应用设置接管或改变执行顺序，才继续查参数拼写与结构；否则先改文档所依据的版本。

## 区分语法仍合法和会被应用丢弃

仓库写明配置文件管理与增强包括 Merge 与 Script。发布说明对 DNS 覆写与扩展配置有多次修正，例如空内容报错、初始值覆盖已有设置、已填写字段残留原配置、空字段缺失；已填写字段被 Merge 或 Script 覆盖；Merge 覆写 DNS 策略、过滤条件与 hosts 时旧条目仍被保留；扩展配置或脚本写入由应用设置接管的字段时记录该值已被丢弃。

若文档把某参数写在订阅正文，而本机用 Merge、Script 或应用设置接管了同一字段，应查看扩展日志是否提示丢弃，而不是只看订阅文本是否仍包含该键。若文档要求 DNS 覆写，注意发布说明写明 DNS 覆写开关按订阅独立记忆，自动关闭仅影响当前订阅；本机现象可能是当前订阅未开启覆写，或重启后状态与文档假设不同。不同来源的订阅或规则集若共用缓存路径，发布说明记载过服务模式无法启动内核，此时应优先核缓存与来源隔离，而不是改单个参数名。

## 失败时的下一步

参数名在当前标签说明中找不到：回到仓库功能列表，确认是否属于 Merge、Script 或内核配置；若只存在于旧转载，停止套用。本机版本低于文档：到发布页获取与文档相同的 Stable 标签再核对，不要在旧安装包上强行加入新字段。本机版本高于文档：从文档声称的标签读到本机标签的全部修复与优化，查找该参数是否改由应用设置接管、是否改变执行顺序。仍无法判断：保留当前配置文本副本，仅对照发布页与仓库说明列出的字段主题，避免把未在这两处出现的第三方参数继续写入。
