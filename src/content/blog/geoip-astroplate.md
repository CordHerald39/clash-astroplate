按地区分流在配置里通常落在 `GEOIP`、`SRC-GEOIP`，有时还和 `GEOSITE`、`IP-ASN` 写在同一列表。结果和预期不一致时，不要先假设国家代码写错，而要按官方给出的匹配顺序、匹配对象和 DNS 行为逐项对照。规则从上到下匹配，顶部优先；任何「看起来像地区」的条目都可能根本没有执行。

## 先确认实际生效的是哪一类地区相关规则

`GEOSITE` 匹配 Geosite 内的域名；`GEOIP` 匹配 IP 所属国家代码；`IP-ASN` 匹配 IP 所属 ASN；`IP-CIDR`、`IP-CIDR6`、`IP-SUFFIX` 匹配地址范围。适用条件必须分开：按域名集合走，应检查 `GEOSITE` 和各类 `DOMAIN*`；按 IP 所在国家走，才检查 `GEOIP`；按自治系统走，检查 `IP-ASN`。判断依据是请求当时拿出的数据——只有域名、已经有目标 IP，还是只有来源 IP。用错类型时，出站策略再怎么改也不会变成「按地区」。

来源与目标接反会直接造成偏差。`SRC-GEOIP` 使用来源 IP 的国家代码；附加参数 `src` 会把目标 IP 类规则改成来源 IP 匹配。具体操作：在列表里找出所有 `GEOIP`、`SRC-GEOIP` 以及带 `src` 的目标 IP 规则。若预期是「访问某国的服务器」，却写了来源侧条件，分流对象从一开始就错了。文档示例分别是 `GEOIP,CN,DIRECT` 与 `SRC-GEOIP,cn,DIRECT`，排查时不要把两条当成同一条来读。

进程、入站、端口规则也可能抢在地区规则之前。`PROCESS-NAME`、`PROCESS-PATH` 及其通配符和正则形式，`IN-PORT`、`IN-TYPE`、`IN-USER`、`IN-NAME`，`DST-PORT`、`SRC-PORT`，`UID`，`NETWORK`，`DSCP` 都在同一列表里按顺序生效。`IN-TYPE` 可以使用 `SOCKS/HTTP` 这种用斜线分隔的写法，`IN-USER` 也支持用斜线分隔多个用户名。排查时要把 `GEOIP` 以上的每一条都视为可能的提前命中，而不是只盯着国家代码那一行。

## 核对解析有没有把目标 IP 交给 GEOIP

域名开始匹配关于目标 IP 的规则时，mihomo 会触发 DNS 解析，用目标 IP 检查是否匹配。地区分流若依赖 `GEOIP`，适用条件是这次解析确实发生，并且解析得到的 IP 才是国家代码的输入。`no-resolve` 可跳过解析；但若更早匹配已经触发过解析，带 `no-resolve` 的目标 IP 规则仍会参与匹配。判断依据：从列表顶部往下看，第一条需要目标 IP 且未跳过解析的规则，会决定 IP 何时出现；其后的 `GEOIP` 无论是否写 `no-resolve`，都可能已经有 IP 可用。

具体操作可以分成四步。第一步，确认请求是域名还是字面 IP，字面 IP 不依赖这次解析。第二步，标出所有目标 IP 类规则及其 `no-resolve`。第三步，看地区规则上方的域名规则是否已经给出站，若已命中则 `GEOIP` 不会执行。第四步，看 `NETWORK`：文档指出请求为 UDP 而节点没有 UDP 支持（例如 ss 节点没写 `udp: true`）时会继续向下匹配，地区结果可能落在更下面的规则或 `MATCH` 上。

逻辑规则要单独拆括号。`AND`、`OR`、`NOT` 的 payload 是规则类型和其他 payload，文档强调注意括号。`SUB-RULE` 匹配至子规则，同样要注意括号。地区条件若写在逻辑组合里，任一端不成立都不会走到预期出站。`RULE-SET` 引用规则集合，需配置 `rule-providers`；集合内部的顺序和主列表一样会改变谁先命中。

## 用 MATCH 和优先级定位不符合预期的落点

`MATCH` 匹配所有请求、无需条件，通常放在最后。若实际出站总是落在 `MATCH` 指向的策略，判断依据是：其上全部规则都未命中，包括以为会命中的 `GEOIP`。下一步应检查国家代码是否写在能执行到的位置、解析是否被跳过，以及是否被 `GEOSITE` 等域名规则提前接走。

若命中的是更靠上的 `DOMAIN-SUFFIX` 或 `GEOSITE`，说明分流按域名完成，地理 IP 数据未参与。这与「按地区」的预期不一致，但符合优先级定义。下一步是把真正要按国家代码处理的流量，从更宽的域名规则里排除，或调整顺序，而不是反复修改 `GEOIP` 的国家代码。通配符类域名和进程规则仅支持 `*` 与 `?`，文档注明这里的通配符和配置文件其他地方的 Clash 格式通配符不相同，误用另一种通配写法也会导致「地区规则从未轮到」。

若已经命中 `GEOIP` 但国家不符合设想，本页能提供的依据是：规则匹配的是 IP 所属国家代码，不是网站所属公司。下一步应核对当时用于匹配的是目标 IP 还是来源 IP，以及该 IP 是否来自本次或前置 DNS。不要把 `IP-ASN` 的自治系统号理解成国家，也不要把 `GEOSITE` 的域名集合理解成 IP 地理。仍无法解释时，回到列表顶部重走：UDP 是否继续向下、逻辑括号是否写错、`REMATCH-NAME` 或入站条件是否插入、子规则是否未进入。
