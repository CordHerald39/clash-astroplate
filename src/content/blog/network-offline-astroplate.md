关闭代理后网站仍然打不开，说明故障往往已经不在节点，而在运行模式并未落到全局直连，或直连出站接口、地址族、路由标记把流量送进了不可用路径。配置上，“关闭代理”对应把运行模式设为全局直连。下列检查只覆盖全局配置里已经写明的项，不把未给出的按钮或效果当作依据。

## 适用条件：怎样判断代理真的关掉了

本检查适用于内核仍在运行，且你希望流量不再进入代理或策略组的场景。运行模式可选规则匹配、全局代理、全局直连，默认规则模式。全局代理需要在 GLOBAL 策略组选择代理或策略，因此若模式仍是全局代理或规则匹配，即使主观上认为已经关闭，流量仍可能被分流。判断依据是配置中的 mode 值为 direct，而不是其他未文档化的名称。

若日志级别为静默，控制台和控制页面都不会输出，应先改为错误级，才能看到“发生错误至无法使用”的记录。尚未完成这一步时，不要把“打不开”直接归因于网站本身。外部控制器、TLS 证书、外部用户界面路径属于控制面，不解释关闭代理后的网页访问。

## 直连路径上应优先核对的项

先核查出站接口。mihomo 的流量出站接口由该项指定，文档示例为 en0。关闭代理后连接不再经节点转发，但仍从该接口离开主机。接口名与系统设备不一致时，直连同样失败。未配置则跟随系统默认路由，应把系统路由、地址和链路状态并列检查。

再核对 IPv6。是否允许内核接受 IPv6 流量，默认允许。关闭代理后若站点只发布 IPv6，而此项为假，会表现为全面打不开。TCP 并发启用后，会使用 DNS 解析出的所有 IP 并采用第一个成功的连接；错误地址族上的失败可能只出现在日志里，需要把日志级别调到能看见这些失败。统一延迟会计算 RTT 以消除握手带来的节点类型差异，它不决定直连能否离开主机，关闭代理后的不通不要先改这一项。

Linux 环境核查出站路由标记。该项为出站连接提供默认流量标记，文档示例为 6666。直连流量若带有该标记，可能被本机或上游防火墙丢弃，表现就是关闭代理也不通。把标记与防火墙、策略路由对照，是这一步的判断依据。

TCP Keep Alive 的间隔、最大空闲时间以秒计，文档示例均为十五秒；禁用项在 Android 上强制为真。它们用于减少移动设备耗电。只有日志指向空闲断开时才值得调整，不应作为“打不开网站”的首选解释。进程匹配模式在路由器上推荐关闭；若设备是路由器且仍为强制匹配所有进程，可改为不匹配后再观察，以免把进程识别误差当成网站故障。

## 入站残留与失败后的下一步

若失败的是其他设备而不是本机，应检查允许局域网、绑定地址、允许与禁止的地址段、以及用户验证。允许局域网为真时，其他设备可经代理端口访问互联网。绑定地址为星号表示绑定所有 IP，也可绑定单个 IPv4 或单个 IPv6。局域网允许地址段仅在允许局域网为真时生效，默认包含 0.0.0.0/0 与 ::/0；禁止地址段黑名单优先级更高，文档示例包含 192.168.0.3/32。http(s)、socks、mixed 可配置用户验证，并可以设置跳过验证的 IP 段，文档示例为 127.0.0.1/8 与 ::1/128。本机直连失败先查出站接口与地址族；他机失败再查绑定与验证。

GEO 数据模式、加载器、自动更新间隔、自定义 UA、ETag 支持只约束地理数据与外部资源下载，不解释关闭代理后的网页失败，第一轮不要列入。缓存可储存策略组选择和 fakeip 映射，影响的是下次启动是否复用旧选择，也不能单独说明当前直连为何失败。

若上述项都与预期一致仍不通，下一步把日志升到信息或调试，确认内核是否仍按全局直连工作，以及出站接口是否在运行中被改变。仍无记录则检查进程是否在读你以为的那份配置。不要在这一步改 GEO 下载或统一延迟。
