当同一台电脑上其他应用已经按预期策略转发，只有某一个浏览器不符合时，应优先怀疑该浏览器进程的入站路径或进程匹配结果与其他进程不同，而不是先改全局规则。适用条件是：内核 `mode` 对其他进程表现正常，问题可复现于单一浏览器。手册可依据的字段是 `find-process-mode`、入站验证、局域网限制、IPv6 与日志级别。下列步骤不引入未记载的浏览器菜单名称。

## 把该浏览器当成独立进程看

`find-process-mode` 取值为 `always`（强制匹配所有进程）、`strict`（默认，由 Clash 判断是否开启）、`off`（不匹配进程，手册推荐在路由器上使用）。若该项为 `off`，内核不会按进程区分，此时只有某个浏览器异常更可能来自该浏览器根本没把流量送进 Clash，而不是规则写错。若为 `always` 或 `strict`，则该浏览器进程名可能被单独匹配，从而与其他浏览器走向不同。判断依据：仅该浏览器的流量在日志中带有不同的进程信息，或其他浏览器有进程匹配而它没有。

不要在这一步修改策略组选择。`profile` 下 `store-selected` 为 true 时会储存 API 对策略组的选择供下次启动使用；排查单个浏览器时，改策略组会污染对照，应先保持该项，只观察进程匹配是否对该浏览器生效。

## 确认流量有没有进 http、socks 或 mixed

该浏览器若使用扩展或自身代理设置，可能直连内核入站，也可能完全绕开。`authentication` 要求用户名和密码；`skip-auth-prefixes` 允许指定 IP 段跳过验证，文档示例为 `127.0.0.1/8` 与 `::1/128`。若该浏览器连到非本机地址，或未携带验证信息，就会表现为不走预期策略，其实是没能进核。判断依据：其他浏览器有入站记录，该浏览器没有，或出现认证失败。

`allow-lan` 为 true 时才允许其他设备经代理端口访问；本机浏览器一般走回环，但若扩展填了局域网 IP，还要看 `bind-address` 以及 `lan-allowed-ips`、`lan-disallowed-ips`（黑名单优先）。判断依据：该浏览器使用的目标地址不在绑定范围或命中禁止网段。

## 用模式和日志做交叉验证

`mode` 为 `rule`、`global` 或 `direct`。若全局已是 `direct`，任何浏览器都不应再按规则出站，此时不能把单一浏览器的直连当成故障。若为 `global`，则预期是全部走 GLOBAL 策略组，单一浏览器若仍直连，说明它可能没进核。将 `log-level` 设为 `info` 或 `debug`，在控制台或控制页面对比该浏览器与其他进程的记录；`silent` 无法用于这一步。

`ipv6` 默认为 true。若该浏览器优先使用 IPv6 而其他浏览器使用 IPv4，且内核未按预期接受某一侧流量，可对照该项。失败时下一步：先确认 `find-process-mode` 不是 `off`；再确认该浏览器目标端口带有正确验证且来源落在 `skip-auth-prefixes` 或允许网段；然后将 `mode` 在 `direct` 与 `rule` 之间切换一次，看该浏览器是否随模式变化。若模式变化时它完全不动，按未进入 Clash 入站处理，而不是继续改路由规则。`external-controller` 不能替代进程日志。
