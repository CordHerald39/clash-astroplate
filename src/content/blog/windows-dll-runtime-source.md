Windows 启动 Clash Verge Rev 时提示缺少 `VCRUNTIME...dll`，属于本机运行环境问题。开发者 FAQ 说明，缺少 VC 运行库会产生这类提示，并注明 2.0 版本后的安装器会自动检测和安装 VC runtime。先看自己使用的版本和安装方式，再决定补装环境，不能把一个 DLL 错误当作节点故障。

## 从提示中保留必要信息

记录缺失的完整 DLL 名、客户端版本、安装包架构及安装器是否给过运行库提示。若下载的是压缩包、从旧目录启动或安装中途取消，先确认实际运行文件来自哪个位置。不要随意把系统 DLL 复制进应用目录。

FAQ 按 x64、x86、arm64 列出运行库入口；应跟随开发者文档中的官方链接，按实际程序与系统需求选择。运行库架构不能只看“电脑是 64 位”一句话推断所有程序。对当前客户端安装包，首先核对其对应架构。

## 选择完整运行库安装器

回到开发者 FAQ，从列出的运行库链接取得安装器，核对页面和文件来源。不要用“下载这个 DLL 放进 System32”的搜索结果代替完整运行库安装。运行库包含一组匹配组件，单文件复制可能留下版本或依赖不一致。

如安装器提供修复选项，先按安装器指导处理，保留错误代码。若安装被组织策略限制，应交给设备管理员处理；没有明确错误依据时，不需要关闭杀毒软件或改系统目录权限。

## 补装之后仍报错

完全退出旧实例，再从确认过的安装位置打开客户端。若仍提示同一个缺失项，检查是否实际启动了另一份旧副本，运行库安装是否完成，以及程序架构是否与下载相符。若缺失 DLL 名已经变化，把新错误作为新的线索记录。

本步骤只验证程序能否启动；窗口出现之后再核对订阅与连接，不能把运行库安装成功写成代理已经可用。相关：[系统与安装包架构](/blog/package-arch-astroplate/)。资料：[开发者 Windows FAQ 中 VC 运行库说明与下载入口](https://www.clashverge.dev/faq/windows.html)。本文没有下载执行运行库安装器，也没有设备亲测结论。
