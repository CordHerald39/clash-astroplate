开机后能看到 Clash Verge Rev 客户端在运行，只说明图形进程被拉起来了，不说明连接可用。该项目内置 mihomo 内核，并提供系统代理与 TUN。发布说明多次把「应用已启动」和「内核无法启动」「TUN 不可用」「系统代理读状态报错或指向失效端口」分开处理，因此排查应从内核与出口是否有效入手，而不是反复开关窗口。

## 适用条件

适用于已安装的 Clash Verge Rev 电脑端：开机或登录后界面出现，但经系统代理或 TUN 访问失败。仓库写明支持 Windows、Linux 与 macOS 11+；发布说明写明 Windows 不再支持 Win7。若内核根本没起来，首页仍可能曾错误显示服务模式，该问题在发布说明中有对应修复，故不能用首页模式文字代替连接诊断。开发命令 `pnpm dev` 会保留服务是否安装的状态，与安装包环境不同，结论不能混用。

若开机时网络尚未获得地址，或另有 VPN 接管网络，应先归到发布说明已记载的「网络未就绪 / VPN 接管」，而不是直接断定订阅失效。

## 按层次检查

第一层：内核是否在运行。连接失败时先确认内核是否仍在。macOS 发布说明指出：VPN 接管网络或开机网络未就绪时，服务模式内核无法启动、TUN 不可用、系统代理状态读取报错；启动或重启应用时也可能偶发内核启动失败，并误提示「需要更新系统服务」。判断依据：内核未运行时，任何「客户端在」都不应解释为连接正常。Windows 上服务已停止时，还曾出现启动后约两分钟才显示窗口的情况，窗口晚出现不等于内核已好。

第二层：系统代理是否指向有效端口。macOS 修复过服务模式内核意外停止后，系统代理仍指向失效端口导致无法上网。判断依据：系统代理的地址与端口应指向当前仍在监听的内核，而不是已经退出的旧端口。内核停了但代理设置还在，会表现为客户端还在、应用连不上。

第三层：TUN 与服务模式。需要虚拟网卡时，要单独看 TUN 是否可用。发布说明中 Windows 的系统盘权限误判、系统隔离权限误判，以及 Linux 安装或修复服务后仍无法启动内核、开启 TUN，都会造成界面在、TUN 不在。服务因路径、目录权限、数据目录所有权（首次以管理员身份启动）拒绝拉起内核时，连接同样会失败。判断依据：你实际走的是系统代理还是 TUN，只检查对应那一条。

第四层：重启后配置是否仍是你以为的状态。发布说明修复过：订阅包含自定义 DNS 时，确认开启的 DNS 覆写在重启应用后被自动关闭。还修复过不同来源订阅或规则集共用缓存路径时，服务模式无法启动内核。文件错误日志会显示具体路径和失败原因。判断依据：重启后 DNS 覆写、订阅与规则集是否仍能被内核加载，而不是只看客户端窗口。

## 失败时下一步

优先读服务模式的运行日志。发布说明写明服务自身日志会保存到文件，用于追查内核被停止的原因；内核启动失败和服务模式内核意外停止的提示会显示具体原因，窗口恢复后还会提示尚未解决的错误。Windows 服务安全检查失败时会说明原因。应先根据这些文本判断是权限、服务未装、残留服务，还是资源文件问题。

若日志指向服务异常：Windows 可关注未安装服务时普通权限无法启动内核、旧版服务状态残留、安装失败提示「program not found」。macOS 可关注残留服务进程、用户目录在外置磁盘、误报需要更新系统服务。不要在内核未运行时去调节点。若内核在、代理端口有效、仍失败，再查 DNS 覆写是否在重启后被关、规则集是否加载失败。网络未就绪导致的启动失败，应在网络可用后再次手动拉起内核，确认是否可恢复，再决定是否需要重装服务或改用 Sidecar。
