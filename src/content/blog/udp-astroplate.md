网页能打开、实时应用异常，只能说明当前全局配置下至少有一条短 TCP 请求路径可用，不能推出长连接、进程识别或非网页流量同样成功。全局配置里与此对照最直接的是运行模式、日志级别、进程匹配、TCP Keep Alive、TCP 并发、IPv6、出站接口和策略选择是否被保存。下面按适用条件给出步骤和判断依据，失败时只推进到下一层核对，不把网页成功当成实时应用已经恢复。

## 适用条件：把网页成功限制在短 TCP 请求

适用条件是：浏览器访问网站正常，但即时通讯、会议、长连接客户端等实时应用异常。网页成功通常只证明在当前 `mode` 下，某条 HTTP 或 HTTPS 的 TCP 路径能完成请求。实时应用可能依赖连接长时间不中断、依赖进程是否被匹配，或走不同地址族。

`mode` 为 rule、global 或 direct。global 需要在 GLOBAL 策略组选择代理或策略。若网页命中了直连规则，而实时应用命中了需要代理的规则，就会出现一类正常、一类异常。判断依据：先固定记录当前模式，再分别看两类流量是否同一出站路径，不要用网页结果代替应用结果。

`ipv6` 默认为 true。网页若只完成了 IPv4，而实时应用优先 IPv6，内核是否接受 IPv6 会直接造成分化。判断依据：两类流量是否同一地址族。`profile` 里 `store-selected` 为 true 时，会储存 API 对策略组的选择供下次启动使用。网页与应用若表面上同组，重启后实际选中对象可能不同，记录里应包含该项是否开启。

## 排查步骤：日志、进程匹配、保活与并发

第一步，提高 `log-level`。silent 不输出，无法对比两类流量；error 只留下发生错误至无法使用的日志；需要看到一般运行内容时用 info；要对齐网页进程与实时应用进程是否都被处理时用 debug。日志仅在控制台和控制页面输出。判断依据：同一时间窗口内，网页有记录而实时应用无记录或只有无法使用的错误，应优先查是否未被匹配或未被接受，而不是先改其它无关项。

第二步，核对 `find-process-mode`。always 强制匹配所有进程；strict 为默认，由 Clash 判断是否开启；off 不匹配进程，文档推荐在路由器上使用。浏览器进程往往容易被识别，部分实时应用以独立进程、子进程或服务形式出现。判断依据：若接管依赖进程，而当前为 off，实时应用不会按进程被识别，网页却可能靠其它条件成功。此时下一步不是继续用网页测试，而是确认当前模式是否应为 always 或 strict，或改为不依赖进程的判断路径。

第三步，检查 TCP Keep Alive。`keep-alive-interval` 是 Keep Alive 包间隔，单位为秒；`keep-alive-idle` 是最大空闲时间；文档写明修改此项以减少移动设备耗电问题。`disable-keep-alive` 在 Android 上强制为 true。网页请求短，常常在空闲计时前结束；实时应用的长连接更依赖保活是否按设定间隔工作。判断依据：只有在并非 Android 强制禁用的前提下，才能把保活参数纳入长连接异常原因；Android 上不能指望通过改变“是否禁用”来解释保活，应把排查转到模式、进程匹配、IPv6 和日志。

第四步，查看 `tcp-concurrent`。启用后会使用 DNS 解析出的所有 IP 进行 TCP 连接，并使用第一个成功的连接。网页对“任一 IP 成功即可”往往不敏感；实时应用若对失败切换或具体地址敏感，表现会不同。判断依据：该项只作用于 TCP 并发连接，网页恢复不能证明实时应用的长连接或非 TCP 部分正常。

第五步，核对出站接口与标记。`interface-name` 为流量出站接口；`routing-mark` 为 Linux 出站默认流量标记。网页和实时应用若被送到不同出口，会出现一类成功、一类失败。判断依据：两者是否共用同一接口与同一标记。

## 失败后的下一步

若 debug 下仍看不到实时应用：下一步检查 `find-process-mode` 是否为 off，以及该应用是否根本未进入内核。路由器场景按文档使用 off 时，不要用进程名解释网页与应用的差异。

若仅 Android 长连接异常：下一步不要把希望放在 `disable-keep-alive` 可被关闭上（该页写明强制为 true），改为核对间隔与空闲时间是否仍按你的意图配置，并回到模式与 IPv6。若网页与应用地址族不同：下一步单独对照 `ipv6`，避免用 IPv4 网页成功为 IPv6 实时应用背书。

若 global 模式下网页可用、应用不可用：下一步确认 GLOBAL 策略组选择的代理或策略对两类流量是否同一对象，并核对该选择是否被 `store-selected` 保存。网页正常只说明短 TCP 请求可完成，不能外推为实时应用可用性保证。
