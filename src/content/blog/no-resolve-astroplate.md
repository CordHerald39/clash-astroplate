在 Clash（mihomo）某条目标 IP 规则末尾加上 `no-resolve` 之后，出站结果可能变、也可能不变。解释变化只能依据官方对附加参数的定义：该参数仅支持关于目标 IP 的规则；域名开始匹配这类规则时本会触发 DNS 解析以检查目标 IP，加上后则跳过这次解析。同时，若更早的匹配已经触发过解析，带该参数的目标 IP 规则依旧可以命中。

## 适用条件

本解释适用于改动发生在 `IP-CIDR`、`IP-CIDR6`（二者效果相同）、`IP-SUFFIX`、`IP-ASN`、`GEOIP` 这类目标 IP 规则上，并且请求是带着域名进入匹配的场景。文档示例为 `IP-CIDR,127.0.0.0/8,DIRECT,no-resolve`。若改的是 `DOMAIN`、`GEOSITE`、`DST-PORT`、`MATCH` 等非目标 IP 规则，本页并未赋予 `no-resolve` 语义，结果变化不能用“跳过 DNS”来解释。规则从上到下匹配，解释任何结果都要连同该条上方的规则一起看。

## 结果变了时对应哪一种机制

常见变化是：原先命中某条 `GEOIP` / `IP-CIDR` / `IP-ASN` / `IP-SUFFIX`，加上 `no-resolve` 后改由更下方的规则（包括最后的 `MATCH`）接手。判断依据是：轮到该条时目标 IP 尚不存在，域名开始匹配目标 IP 规则本应触发解析；跳过解析后，本条无法用“刚查到的目标 IP”做范围或国家代码比对，于是继续向下。这与删除该条不同——类型和载荷仍在，只是本条不再充当“第一次为匹配而解析”的触发点。

若变化表现为“直连/代理对调”，先确认发生变化的是同一条目标 IP 规则的命中与否，而不是逻辑规则 `AND`/`OR`/`NOT` 括号改写、或 `RULE-SET` 集合内容被一并改动。`src` 会把目标 IP 匹配转为来源 IP 匹配，若同时加了 `src`，结果变化应优先按来源 IP 解释，不能全部算在 `no-resolve` 上。

## 结果没变时如何解释

官方第二句决定了“加上参数但出站不变”同样可以成立：更早的匹配若已触发 DNS 解析，则依旧会匹配到带 `no-resolve` 的目标 IP 类规则。判断顺序如下：

- 上方是否已有未带 `no-resolve` 的目标 IP 规则被走过，从而已经得到目标 IP。
- 请求本身是否并非“域名开始匹配目标 IP 规则”，而是目标地址已是 IP，本就不必为核对规则去解析域名。
- 该条上方是否早已被 `DOMAIN`、`GEOSITE` 等命中，请求根本没有落到被修改的那一行。此时出站不变，与有没有 `no-resolve` 无关。

三种情况都不是参数失效，而是“跳过的是本条触发的解析”，不是“禁止使用已有目标 IP”。

## 解释不通时下一步

若既不能用“本条跳过解析故未命中”、也不能用“更早已解析故仍命中”说明结果，下一步不要继续堆叠同类 IP 规则，而是核对：该行是否确实是目标 IP 类型、参数是否写在出站名之后、列表顺序在修改前后是否一致。逻辑规则要注意括号与 payload 形态。确认配置与文档示例同构后，再根据从上到下的优先级列出“第一条会触发解析的目标 IP 规则”和“带 `no-resolve` 的规则”的前后关系，重新解释结果。
