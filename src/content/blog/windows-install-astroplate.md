## 适用条件：先分清「向导失败」还是「装完后的服务报错」

本说明只覆盖 Windows 上 Clash Verge Rev 官方安装包在安装向导阶段失败，或向导刚结束就出现安装/服务相关原文报错时，如何把信息收全。官方发布页写明 Windows 不再支持 Win7，安装包按架构分成 64 位与 ARM64，并另提供「内置 Webview2」安装包。系统版本、CPU 架构、安装包文件名对不上时，后面收集到的内容很难对照官方修复记录。

先做三步核对，再开始抄报错：安装包是否来自官方 GitHub 发布页；完整文件名是 `x64-setup`、`arm64-setup` 还是带 `fixed_webview2-setup`；失败发生在向导尚未走完，还是文件已经写入后、服务或内核相关提示弹出。后一类在较新正式版里已单独改过提示和日志，不要和向导窗口中途退出写成同一件事。仓库说明配置与日志只保存在本地，排查以本机弹窗原文和本机文件名为准。

## 安装向导失败时必须留下的信息

有效错误信息要能回答「哪一个包、哪一台机器、哪一句原文」。至少固定记录下面五项，缺任何一项都难以对照发布说明。

完整安装包文件名。发布页把「正常版本（推荐）」和「内置 Webview2 版」分开：后者体积更大，说明仅在企业版系统或无法安装 WebView2 时使用。向导若在界面依赖阶段停下，文件名能判断是不是选错了发行物。

系统架构与 Windows 版本。x64 包和 ARM64 包不能混用；Win7 已被明确排除。把系统显示的版本、是否为企业版或被精简过的环境一并记下。不要只写「Windows 电脑」。

报错原文，按弹窗逐字抄录。官方更新里出现过安装服务失败提示「program not found」、只显示「服务无法启动内核」、系统盘根目录删除权限被误判、系统隔离权限被误判等表述。只保存「安装失败」无法和这些条目对齐。多行提示要整段保留；若提示里带了修复说明或文档链接，链接也要一起记下。

失败发生在哪一步。例如写入安装目录、请求管理员权限、安装系统服务、还是第一次启动。较新版本处理过「旧版服务状态残留导致无法重装」「路径或目录权限导致服务无法启动」以及重装服务后内核缺失等问题。步骤不清楚，就无法判断是否属于已记录的修复范围。

是否曾经装过旧版。若本次是升级或重装，写下一次使用的版本号，以及是否手动删过服务或安装目录。发布说明中有自动备份可识别残留并尝试恢复安装的记录，有无旧安装会改变对照方向。

不要用转述代替原文。官方强调数据留在本机，排查时以当次弹窗和当次下载的文件名为准。

## 用这些信息决定下一步，而不是反复重试同一个包

收集齐之后按原文分流。系统仍是 Win7：官方已不再提供该系统安装包，需要先换到受支持的 Windows，再谈向导是否成功。文件名架构与设备不符：改下发布页对应的 64 位或 ARM64 包，不要继续用当前这个文件重试。

环境是企业版，或本机无法安装 WebView2，而当前用的是「正常版本」：改用发布页标明的内置 Webview2 安装包再试。若并非这类环境，应优先用标注为推荐的正常版本，避免把两类失败叠在一起。

原文里出现「program not found」、服务残留无法重装、权限被误判、服务因路径或目录权限起不来：先核对自己是否已换到包含对应修复的较新正式版。发布说明中连续版本处理过服务安装失败提示、权限误判、旧服务状态残留，以及安全检查失败时不再只显示「服务无法启动内核」、改为说明原因并给出修复文档链接。换包前务必保留刚才抄下的原文，用来对比新提示是否已经变成带原因的说明。

向导已经走完，但内核或服务仍起不来：较新版本会把服务自身运行日志保存到文件，并优化文件错误日志（显示具体文件路径和失败原因），升级后还会在服务版本或协议不兼容时提示重新安装。此时应保存应用给出的完整原因和路径，而不是只截旧的一句「服务无法启动内核」。官方仓库把安装说明和 Windows 常见问题指向文档页，用同一份原文去对照即可。

按文件名、架构、版本分流后向导仍失败：把完整安装包文件名、Windows 版本与架构、弹窗原文、失败步骤发到官方仓库的 Issue。缺少原文或文件名的反馈，无法和已修复条目对齐。安装包始终使用官方 Release 中的 setup 文件；发布页同时提供对应的 `.sig` 文件，可用来核对应下载是否完整，避免把损坏安装包当成向导缺陷。
