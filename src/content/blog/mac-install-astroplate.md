## 先判断卡在“应用起不来”还是“起来后网络不对”

Clash 电脑端（macOS）打不开时，应先区分两类现象。第一类是进程或窗口根本出不来，或一启动就提示内核失败、需要更新系统服务、无法继续使用 Sidecar。第二类是界面已经能进，但订阅、规则、系统代理或 TUN 不工作。官方发布说明里，macOS 启动/重启时偶发内核启动失败、误提示「需要更新系统服务」、残留服务进程导致内核无法启动、部分账户安装或修复服务时无法解析用户组，都属于第一类。DNS 覆写、订阅缓存、规则集合更新失败等，属于应用已经运行之后的配置问题。

判断依据是：若连图形界面或内核都没有稳定起来，配置文件对错无法被验证，此时先查安装包来源与架构，而不是先改订阅。仓库要求到 Release 页下载对应安装包，并写明 macOS 11+、Intel 与 Apple 两套包。来源或架构错误时，表现就是打不开或启动即失败，这与配置内容无关。

## 来源核对：官方 tag、架构、完整 dmg

无法打开时，第一步只核来源。打开 GitHub 仓库给出的 Release 页，确认文件来自 Stable 的正式 tag，而不是已废弃的 Alpha，也不是标注可能存在缺陷的 AutoBuild（除非你明确在做测试反馈）。Apple 芯片只对应 `aarch64.dmg`，Intel 只对应 `x64.dmg`。架构下错，优先换包，不要先导入配置。

第二步看包是否完整、是否被改名转手。同一 tag 的资产列表会列出 dmg、可选的 `.app.tar.gz` 和签名文件。应以该列表中的原始文件名为准。来路不明的压缩包即使能拷进「应用程序」，也不能当作官方构建。Windows 的 exe 与 Linux 的 deb/rpm 不能用来排除 macOS 打不开的问题。

第三步才看本机残留，而不是订阅。v2.5.6 写明：残留的服务进程会导致内核无法启动，「继续使用 Sidecar」失败且无法修复；部分账户安装或修复服务时提示无法解析用户组。v2.5.7 写明：启动或重启时偶发内核启动失败，并误提示「需要更新系统服务」。这些提示指向服务/内核启动链，仍属于“应用能否跑起来”，不是规则写错。用户目录若在外置磁盘，官方还提示服务可能拒绝启动内核，应先按发布说明给出的原因处理目录与服务，而不是先改代理规则。

## 配置放到界面能稳定打开之后；失败则换包或修服务

仅当窗口能反复打开、内核不再在启动瞬间退出时，再查配置。此时才轮到订阅是否含自定义 DNS、系统代理是否仍指向已失效端口、TUN 是否因开机网络未就绪而不可用。v2.5.6 提到服务模式内核意外停止后，系统代理仍指向失效端口会导致无法上网——那是“已经打开过、内核曾经起来过”之后的网络状态，用来解释打不开会误判。

若来源正确、架构匹配，启动仍失败：按发布说明处理残留服务进程、重新安装或修复服务、核对用户组解析与用户目录位置；不要靠反复开关系统代理来“试开”。若换过芯片或从非官方包迁来，删除错误包，回到同一 Stable tag 重下对应 dmg。配置排查只有在应用可启动之后才有意义。
