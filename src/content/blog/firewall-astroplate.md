Clash 在某一网络能用、换到另一网络失败时，优先核对会随网卡地址、来源网段和出站网卡一起变化的全局项，而不是先改代理组节点。官方全局配置里，`bind-address` 可绑定 `"*"`、单个 IPv4 或单个 IPv6；`allow-lan` 为 `true` 时才允许其他设备经过代理端口；`lan-allowed-ips` 默认包含 `0.0.0.0/0` 与 `::/0`，`lan-disallowed-ips` 默认空且优先级更高。`interface-name` 指定 mihomo 的流量出站接口。这些项在 DHCP 更换、IPv6 有无、网卡名变化时，会出现“上一网络正常、下一网络全部失败”的割裂，需要按网络差异对照，而不是当成随机故障。

## 先对照绑定地址是否还属于当前网络

适用条件是：同一份配置在网络 A 可用，网络 B 上代理端口连不上，或只有部分地址族失败。判断依据是 `bind-address` 是否写成了某一具体地址。文档写明 `"*"` 绑定所有 IP 地址；`192.168.31.31` 这类写法绑定单个 IPv4；`[aaaa::a8aa:ff:fe09:57d8]` 这类写法绑定单个 IPv6。若绑定的是网络 A 上的地址，网络 B 上该地址不存在时，监听不会落到当前网卡，表现就像整网被拦。

操作上应记录网络 B 的本机地址族后再读配置：若当前只有 IPv4 却绑定了某一 IPv6，或相反，即可判定为绑定与网络不匹配。`ipv6` 控制是否允许内核接受 IPv6 流量，默认为 `true`；若网络 B 无 IPv6 或中间设备丢弃 IPv6，只把失败当成“节点不行”会扩错范围。失败时下一步：在确认问题随网络切换复现后，将 `bind-address` 改为 `"*"` 做对照，同时不要并行修改 `mode`。`mode` 默认为 `rule`，还可为 `global` 或 `direct`，它不负责选择监听网卡。

## 再对照来源网段、认证与允许局域网

适用条件是：本机在网络 B 上能访问，但同一局域网内其他设备不能；或相反。此时应读 `allow-lan`：为 `false` 时，其他设备不能经过代理端口访问互联网，与当前是 Wi-Fi 还是有线无关，只与是否允许非本机入站有关。为 `true` 时，再读 `lan-allowed-ips` 与 `lan-disallowed-ips`。不同网络的来源前缀不同，上一网络的白名单可能根本不覆盖新前缀；黑名单若写入了某网段，新网络一旦落入该段会被直接禁止。

判断依据仍然是黑名单高于白名单。`authentication` 作用于 http(s)/socks/mixed 代理用户验证；`skip-auth-prefixes` 设置允许跳过验证的 IP 段。网络切换后，来源可能不再属于原先可跳过的前缀，于是从“免认证可用”变为“必须带用户口令”。失败时下一步：确认新来源是否落在黑名单、是否仍被白名单覆盖、是否仍满足跳过认证的前缀。不要把 `external-controller` 从 `127.0.0.1:9090` 改到 `0.0.0.0` 当作修网络切换的手段——那是 API 监听范围，不是代理端口的局域网名单。

## 最后对照出站接口、进程匹配和日志

适用条件是：入站已经能连上代理端口，但网络 B 上实际访问失败，或只有特定进程失败。`interface-name` 指定出站网卡；网络 A 的接口名在网络 B 上可能不存在或指向未承载默认路由的网卡，于是出现“入站成功、出站全灭”。Linux 上的 `routing-mark` 为出站连接提供默认流量标记，同样不随无线/有线自动改写，换网络后若系统路由策略依赖标记，需要单独核对，而不是加局域网白名单。

`find-process-mode` 可选 `always`、`strict`（默认）、`off`，路由器上推荐 `off`。它决定是否匹配进程，不能记录“当前是哪一种接入网”，但会在不同设备形态上放大差异。日志方面，`log-level` 仅在控制台和控制页面输出；网络切换排查时应避免 `silent`，需要更多信息时用 `info` 或 `debug`。`keep-alive-interval`、`keep-alive-idle` 与 `disable-keep-alive`（Android 上强制为 `true`）用于 TCP Keep Alive 与耗电，不能解释“换 SSID 后绑定地址失效”。失败时下一步：一次只改出站接口或只改入站名单，对照日志里连接是否建立；确认官方全局项与当前网络地址一致后，若仍失败，再检查该页未描述的系统路由或运营商侧限制，而不是继续堆叠 `lan-allowed-ips`。
