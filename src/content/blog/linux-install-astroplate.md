Linux 上 Clash Verge Rev 启动失败时，不要先当成「包坏了」或「订阅坏了」。应先分成两类：包、服务、权限、内核文件能否运行，属于依赖与运行环境；订阅、覆写、缓存路径、数据目录所有权导致内核拒绝加载，属于配置。较新版本会显示内核启动失败的具体原因，并把服务运行日志保存到文件。排查以这些原文为准，而不是反复重装同一个文件。

## 适用条件

适用于窗口无法保持、提示内核无法启动、安装或修复服务后仍不能拉起内核或打开 TUN、升级后提示服务版本或协议不兼容。客户端已运行、只是个别网站不通，不属于启动失败。安装命令在 apt / dnf 就退出时，先回到发行版与架构识别，不要编辑配置。

## 依赖与环境：怎样判断

1. 失败发生在安装命令，属于包依赖或架构错误，尚未进入客户端。
2. 提示指向系统服务、TUN、重新安装服务。发布记录写明：升级后服务版本或协议不兼容会提示重装；Linux 上曾出现安装或修复服务后仍无法启动内核、开启 TUN。这类按服务组件处理。
3. 近期用提升权限启动过。说明提到首次以管理员身份启动后，服务可因数据目录所有权不符拒绝启动内核。先核对目录归属，不要先改配置文件。
4. 重装服务后内核缺失、Sidecar 也无法使用，更像内核文件或安装残留。
5. 首页写着服务模式不等于内核在运行；曾有内核未运行时首页仍显示服务模式的问题。提示中出现服务、权限、目录、内核缺失、协议不兼容，按环境处理。

## 配置问题：怎样判断

客户端已能打开，或日志给出了具体配置路径时再查配置。

1. 文件错误日志会显示具体路径和失败原因。路径落在订阅、Merge、Script、DNS 覆写上，属配置；路径落在服务程序或内核二进制上，仍属环境。
2. 不同来源订阅或规则集共用缓存路径时，服务模式可以无法启动内核。多个订阅同时失败且提到缓存路径，先隔离订阅。
3. 错误落在 DNS 覆写、Merge、Script（空内容、字段被覆盖、空字段缺失等），属于覆写链，不是缺库。
4. 订阅更新失败要以当前版本给出的真实原因为准，不要把超时写成缺依赖。

## 仍分不清时下一步

一次只改一类变量：先关掉额外覆写、只留一份订阅。能启动则问题在配置链。仍不能启动，则保存窗口完整报错和服务运行日志（避免强制结束内核造成最后日志丢失），连同版本号与包文件名，对照该版本 Release 的 Linux 服务与内核条目，再决定修服务还是换匹配的安装包。
