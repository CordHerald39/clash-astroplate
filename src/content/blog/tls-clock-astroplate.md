下载配置时若提示证书时间错误，需要先判断失败停在 TLS 还是已经得到 HTTP 结果。官方材料是 HTTP 响应状态码列表：它们指示特定请求是否成功完成，并按 1xx 到 5xx 分组。证书时间比较发生在握手阶段，清单里没有“证书过期”编号。因此“怎么查”是指用有无状态码、状态码类别来决定要不要查本机时间与证书有效期，而不是编造下载界面或关闭校验的步骤。

## 适用条件：何时才优先查证书时间

两条同时满足才优先查时间。其一，下载配置的那次 HTTPS 请求没有产生成功响应：200 表示请求成功；201 表示创建了新资源；204 无正文但首部有用。配置下载通常期望 GET 成功并取得消息体，若从未出现 200，不能说下载已完成。其二，同时也没有可用的客户端或服务器错误码可解释失败。若已经出现 401、403、404、407、451 或 502、503、504，则失败已经被 HTTP 层分类，不应再命名为证书时间错误。

资料指出：若收到未列出的响应，可能是服务器软件的非标准状态。非标准码仍然是 HTTP 响应，说明证书校验已放行到应用层。只有连接在握手处中断、没有任何 1xx–5xx 时，把错误理解为证书有效期与时钟比较失败才与这份材料相容。下载过程中的 304 表示缓存未修改，客户端可继续使用同一缓存副本；这与证书时间错误相反，它证明条件请求已经完成。

## 分层排查的具体操作

记下下载所用的 URL 与方法，只观察有无状态码。若得到 4xx：400 为请求语法或分帧被服务器视为客户端错误；403 是已识别身份但无权限；404 是找不到资源，浏览器中表示 URL 无法识别，API 中也可能是端点有效但资源不存在；405 是方法不被目标资源允许；407 需要代理认证；429 是限流；431 是请求头过大。这些都应查地址、方法、认证和代理，而不是系统时钟。若得到 5xx：500 是通用错误；502 是网关拿到无效响应；503 未就绪，常见于维护或过载，且应尽量带 Retry-After；504 是网关超时。它们指向配置源或中间网关。

仅当完全没有状态码时，才查证书时间：本机时钟是否明显偏离、时区是否错误，以至于当前时刻落在证书起始之前或截止之后。资料不包含操作系统操作说明，因此查的是时间差是否足以让握手失败。校正时钟后用同一 GET 再下载。若变为 200，说明资源已获取；若变为 303，服务器要求用 GET 另取 URI；若变为 307 或 308，必须保持原方法跟随重定向。这些都说明证书时间已不再阻断 HTTP。

## 判断依据与失败时下一步

能读到 2xx 或 3xx，证书时间错误的假设不成立；能读到 4xx/5xx，应按该类含义处理；读不到任何状态，才保留证书时间假设。304 也是否定该假设的证据。若对时后仍无状态码，下一步不要关闭校验——清单从未把关闭 TLS 当作修复手段——而是检查是否其实是 421 误定向、426 需要升级协议，或 511 需要网络认证。若对时后变成 413，是请求体过大；变成 414，是 URI 过长，应缩短配置地址而不是再调钟。若变成 410，资源已永久删除且无转发地址。若以上类别都不出现、握手仍失败，这份 HTTP 材料已经用尽，应停止把所有失败都叫作证书时间错误，改为分别记录“无状态码”与“有状态码及类别”，避免把 502 与时钟问题混为一谈。
