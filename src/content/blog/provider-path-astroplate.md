代理集合提示文件不存在时，先把问题限定在“路径是否指向核心允许且真实存在的文件”，不要先改过滤规则或健康检查。下面按官方字段给出适用条件、检查顺序和判断依据，以及仍然找不到文件时的下一步。

## 适用条件

本检查适用于已声明 `proxy-providers`，且 `type` 为 `http` 或 `file` 的条目。`file` 依赖本地文件已经存在；`http` 把远程内容缓存到本地，首次成功下载前文件可以尚不存在，但路径规则仍要合法。`inline` 使用 `payload`，不依赖这份磁盘文件，若报的是内嵌内容问题，不要按“文件不存在”去改 `path`。

检查前先读启动参数 `-d`，它决定 HomeDir。文档规定：`path` 可选、不可重复；不填写时会使用 `url` 的 MD5 作为文件名。出于安全，路径只允许在 HomeDir 中；要存到其他位置，需设置 `SAFE_PATHS`，语法与本系统 `PATH` 相同（Windows 分号，其他系统冒号）。路径越界时，即使磁盘上真有那个文件，核心也不会按你的意图去读。

## 按类型核对路径

第一步，确认出问题的集合 `name` 在配置里唯一，且没有和策略组重名干扰你的对照。`name` 必须填写、不能重复。用 `name` 定位到那一条后，只检查这一条的 `type`、`url`、`path`，避免把别的集合的缓存误当成当前文件。

第二步，看有没有写 `path`。写了就在 HomeDir 下按相对路径拼接，得到预期绝对位置；没写且 `type` 为 `http`，则预期文件名是该 `url` 的 MD5。判断“路径对不对”的依据是：你正在查看的文件，必须等于这条规则算出来的位置，而不是同目录里名字相近的另一个 yaml。两条集合若共用同一 `path`，属于文档禁止的重复路径，后写入的内容会让你误以为“文件在但内容不对”，应先拆开路径再谈缺失。

第三步，核对安全边界。若计算出的位置不在 HomeDir 内，检查环境变量 `SAFE_PATHS` 是否包含该目录。未包含则按官方限制视为不可用路径，表现可以是读不到文件。`file` 类型还要确认该路径上确实有可读文件；`http` 类型还要区分“路径合法但尚未下载”和“路径根本不被允许”。

第四步，确认不是把 `inline` 的 `payload` 或主配置文件当成了集合缓存。只有 `http` 与 `file` 才会在 `path`（或 MD5 文件名）上产生这份独立文件。

## 失败时下一步

路径核算正确且落在允许目录内，文件仍不存在时，按下载与解析链路继续：`type` 为 `http` 则检查 `url` 是否可访问、`interval`（秒）是否导致尚未完成更新、是否配置了用于下载的 `proxy`、请求头 `header` 是否被远端要求。`size-limit` 默认为 `0` 即不限制，单位字节；若误设过小，下载可能不完整，后续解析也会失败。`http` 或 `file` 解析失败时，文档允许使用 `payload` 作为备用代理，可先维持节点，但不能用它代替把缺失文件的路径修正。若核算结果显示路径越界或重复，回到 `-d`、`SAFE_PATHS` 和各条 `path` 去重，不要反复刷新同一错误位置。
