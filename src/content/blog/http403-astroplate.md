同一订阅在一种网络下能更新、在另一种网络下被报 403 时，对照的是两次请求各自的状态码类别，而不是网络快慢。MDN 说明状态码表示某次 HTTP 请求是否成功完成。403 的标准含义是：客户端没有内容访问权，服务器拒绝给出资源；与 401 不同，服务器已经知道客户端身份。若两条路径的三位码并不都是 403，就不能写成两侧同一种失败。

## 适用条件

适用于同一订阅 URI、相近时段、不同网络接入，且至少一侧被称为 403 的对照。资料边界是 RFC 9110；未列入的码按非标准响应记录，不得强行等同于 403。不涉及客户端里切换网络的操作名称。

对照前先对齐方法。对 GET，200 表示资源已获取并在消息体中传输。一侧 200、一侧 403，才是“成功取出”与“已知身份但无访问权”的并列。一侧其实是 511 或 407，则限制发生在网络准入或代理认证，不能与资源级 403 填进同一格。

## 把网络侧限制和资源侧拒绝分列

建议两列只记：接入概括、三位状态码、是否经过代理。完整订阅地址留在本地。

- 两侧都是 403：规范解释相同。差异更可能是身份材料是否随路径改变，而不是 403 在不同网络被重新定义。
- 一侧 401：该侧未认证，必须先认证才能得到所请求响应，不能与另一侧 403 写成同一原因。
- 一侧 407：认证要对代理完成，结论应写在该路径的代理上。
- 一侧 511：需要认证才能获得网络访问，与订阅资源是否允许该身份无关。
- 一侧 429：该侧在给定时间内请求过多。出口不同时限速计数可以不同，须与 403 分写，并保留时间窗信息。
- 一侧 451：因法律原因无法提供（资料举例包括被审查的页面），不得改称 403。
- 一侧 421：服务器不能针对请求 URI 中的 scheme 与 authority 组合产生响应，应对照两边的方案和主机。
- 一侧 404：找不到资源，或用 404 代替 403 以隐藏资源是否存在。表中必须保留真实码。

若只在某一网络出现 400，应检查该路径是否改写了请求（语法、帧或欺骗性路由等），不要按 403 合并。

## 重定向与 5xx 不要并进 403 对照

某网络若先 3xx 再失败：301、308 为永久改 URI；302、307 为临时改 URI，今后仍应用原 URI；307、308 不得改方法；303 改用 GET。跟随到不同落点时，最终码不能直接相比，须先对齐“是否同一目标 URI 的最终响应”。503 用于维护或过载等暂时不可用，可能带 Retry-After，且暂时响应通常不应缓存；502、504 是网关失败。它们与 403 分属不同类，对照结论要分列。

## 对照后仍无法解释时的下一步

真实码并非双侧 403 时，按邻近码分别处理：511、407 先解决该网络的准入或代理认证；429 降低该时间窗内的请求密度；451 按法律不可提供记录。双侧确为 403 时，说明应写成“身份已知、服务器拒绝资源”，并注明路径是否改变了 scheme、authority 或是否插入代理。不要把 404 的隐藏策略写成权限结论。未列出的状态码保持非标准，不作为 403 对照成立的条件。
