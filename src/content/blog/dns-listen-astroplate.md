当 Clash（mihomo）按配置提供 DNS 服务却无法完成监听时，应围绕手册中的 `listen` 字段做端口与绑定检查，而不是先改 `nameserver` 或 `fallback`。手册将 `listen` 定义为 DNS 服务监听，支持 UDP 与 TCP，示例为 `0.0.0.0:1053`。无法监听通常表现为进程未能在该地址与端口上同时接受 UDP 与 TCP 查询，或客户端按该入口访问时连接被拒绝。排查目标是：配置是否要求打开服务、地址端口如何解析、该端口是否已被占用或无权绑定。

## 适用条件与优先核对的开关

先确认 `enable`。手册写明：如为 `false`，则使用系统 DNS 解析。此时即使写了 `listen`，也不应按「Clash DNS 服务已在该端口工作」去理解；应先决定是否启用，再谈监听失败。`enable` 为 `true` 且配置了 `listen` 时，才进入端口检查。

把 `listen` 拆成地址与端口两部分。示例 `0.0.0.0:1053` 中，地址决定绑定范围，`1053` 是服务端口。绑定 `0.0.0.0` 表示所有接口，绑定某一接口地址则仅该接口，绑定回环则仅本机。手册未规定必须使用 `53`，因此不要用「系统 DNS 默认 53 空闲」代替对实际端口的检查。监听同时涉及 UDP 与 TCP，只确认其中一种套接字空闲，不能判断 DNS 服务已可完整监听。

本项检查适用于：进程启动后报地址占用或绑定失败；本机查询指向该端口无响应；局域网主机访问该端口被拒绝。不适用于：服务已监听但解析结果不符合预期——那是上游 `nameserver`、`fallback`、`nameserver-policy` 等问题。也不适用于：只想改假 IP 网段；`fake-ip-range` 与 TUN 默认 IPv4 参考值是另一层配置。

## 检查端口的具体步骤

第一步，从当前生效配置读出 `listen` 的 IP 与端口，不要凭印象使用 `53`。记下是否为 `0.0.0.0`、链路本地或回环。后续所有探测都必须使用这一对地址与端口。

第二步，在运行 Clash 的同一主机上查看该 UDP 端口与 TCP 端口的占用。使用系统提供的套接字查看方式（例如列出 UDP/TCP 监听表），过滤目标端口。判断依据：若已有其他进程占用同一地址族、同一端口，Clash 无法再绑定；若没有任何进程监听，而 Clash 理应已启动，则属于本进程未成功 bind，而不是「上游 DNS 故障」。

第三步，核对权限与端口号范围。若把端口改到系统保留的低端口，启动用户可能没有绑定权限，表现为监听失败。判断依据是失败出现在 bind 阶段，且更换到非特权端口后占用检查变为「可绑定」。不要把权限问题解释成 `default-nameserver` 未填 IP。

第四步，区分「进程已监听」与「客户端能连上」。对 `0.0.0.0:端口`，本机可用该端口探测；对仅绑定回环的地址，其他主机连该主机的局域网 IP 会失败，这不是端口被占，而是绑定范围不含该路径。手册写明支持 UDP 与 TCP，应用对应协议探测：只做 TCP 连通不能证明 UDP DNS 可用，反之亦然。

第五步，排除把上游地址误当成监听端口。`nameserver`、`fallback`、`proxy-server-nameserver`、`direct-nameserver` 是 Clash 出去问询的目标；`default-nameserver` 用于解析 DNS 服务器的域名且必须为 IP。这些字段里的 `53` 或 DoH URL 不会在本机打开 `1053`。若占用检查显示本机目标端口空闲、Clash 也未监听，应回到 `enable` 与 `listen` 是否被生效配置加载，而不是增加 fallback。

## 判断依据与失败时下一步

可以认为端口侧已定位的依据：能复述 `listen` 的 IP 与端口；UDP 与 TCP 各自占用情况已记录；能区分占用、权限不足、绑定地址不可达三类原因。

若端口被其他进程占用，下一步是结束占用进程或改 `listen` 到空闲端口；改端口后，所有把 DNS 指向旧端口的客户端必须同步，否则会表现为「服务起来了但查询仍失败」。若权限不足，下一步是换非特权端口或按操作系统要求赋予绑定能力，而不是改 `enhanced-mode`。若本机已监听但其他设备失败，下一步检查绑定地址、主机防火墙以及客户端是否使用了 `listen` 中的端口而非 `53`。若占用表显示 Clash 已监听、客户端也打到该入口，查询仍异常，则端口检查结束，应转向上游字段：`nameserver`、`fallback-filter`、`respect-rules` 与 `proxy-server-nameserver`（手册要求遵守路由规则时需配置后者，并提示经代理查询时要避免鸡蛋问题）。
