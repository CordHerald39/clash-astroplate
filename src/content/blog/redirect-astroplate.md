更新订阅或更换地址之后，请求被送到登录页，导入失败，这首先是 HTTP 层的结果，而不是“页面长得像登录框”这一观感。MDN 说明：状态码表示某次请求是否成功完成；成功类（200–299）只说明按该方法完成了对应语义，重定向类（300–399）会把客户端送到另一 URI，客户端错误（400–499）则直接拒绝。登录页出现时，要看最后落在哪一类码，以及重定向是否改变了方法。

## 适用条件

本文适用于：更新后的订阅 URL 返回 3xx 后进入认证或登录相关页面、得到 401/403、或最终 200 但消息体明显不是配置文本。资料边界是 RFC 9110 定义的状态码；未列出的码可能是服务器自定义响应，不能按标准登录流程解释。此处不涉及任何客户端按钮名称，只根据方法与状态码判断“为什么无法导入”。

对 GET 而言，200 的含义是资源已获取并在消息体中传输。若消息体是登录 HTML 而不是配置，HTTP 仍可称请求成功，但导入方拿不到可用配置。不要把 200 自动等同于“订阅已导入”。

## 用状态码判断是未认证、无权限还是被改去别处

常见分流如下：

- 401：语义是未认证。客户端必须先认证自己，才能得到所请求的响应。更新后若服务端改为要求身份，未带凭证的导入会停在这一步，随后的登录页只是认证入口，不是配置。
- 403：客户端没有内容访问权；与 401 不同，此时服务器已知道客户端身份，只是拒绝给出资源。反复提交同一订阅地址不会变成有权限。
- 407：与 401 类似，但认证必须对代理完成。若更新后流量改经需认证的代理，失败点在代理而不是订阅正文。
- 511：客户端需要认证才能获得网络访问。这是网络准入，不是订阅资源本身的登录页，两者不要写进同一原因。
- 303：服务器让客户端用 GET 到另一 URI 取资源。许多“跳到登录页”符合这一语义：原请求无论方法如何，下一跳被改成 GET 登录资源，配置不会出现在该响应体里。
- 302：资源 URI 临时改变，今后仍应使用原来的 URI。若临时落点是登录页，不应把登录页 URL 存成新的订阅地址。
- 307：临时改 URI 且必须保持原方法。若原方法不被登录页支持，可能再看到 405（方法为服务器所知但不被目标资源支持）。
- 308 与 301：永久改 URI。若永久目标本身就是强制认证的入口，更新后无法导入是因为新权威来源要求认证，而不是临时故障。

204 无消息体，不能当配置；203 表示元数据并非与源服务器完全一致，可能来自镜像或备份，即便能打开也不等于权威配置。

## 排除“看起来像登录、其实是别的失败”

400 表示服务器认为请求有客户端错误（语法、帧或欺骗性路由等），不是缺密码那么简单。404 是找不到资源；服务器也可能用 404 代替 403 以隐藏资源是否存在，故“页面像登录失败”时仍要记下真实状态码。410 表示永久删除且无转发地址，应删除缓存和链接，继续导入不会恢复。429 为发送了过多请求，属于限速，不是登录逻辑。451 表示因法律原因无法提供。500 是通用服务器错误；503 为维护或过载等暂时不可用，并提示尽可能带 Retry-After，且这类暂时响应通常不应被缓存成“已更新成功”。

## 仍无法导入时的下一步

先记录完整跳转链上的状态码，而不是只保存最后一页的标题。若链上出现 401 或 511，先解决认证再谈导入；出现 403 则应更换有权限的凭证或资源，而不是重试同一未授权请求。若 303/302/307 把 GET 送到登录资源，最终 200 只证明登录页取成功，应回到更新前的订阅 URI 语义：302/307 今后仍用原 URI；仅 301/308 才把来源改为 Location 中的永久 URI，并且要确认该 URI 在认证之后返回的是带消息体的成功响应，而不是再次 401。方法被重定向改掉后出现 405，应核对该跳是否违反 307/308“不得改方法”的约束。未列入的状态码当作非标准响应，不要解释成某一种登录成功。
