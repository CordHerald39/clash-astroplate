## 适用条件：IP 规则不命中时要核对什么

当 `IP-CIDR`、`IP-CIDR6`、`IP-SUFFIX`、`IP-ASN` 或 `GEOIP` 没有把请求送到预期策略时，应先核对实际参与匹配的地址是什么，而不是先改网段文本。适用条件是：配置里确实存在针对目标 IP 或来源 IP 的规则，且该行位于 `MATCH` 之前。规则按从上到下顺序匹配，顶部优先级更高；若更早的域名规则已经命中，后面的 IP 规则根本看不到这次请求。这不属于网段写错，而属于比较对象从未进入 IP 规则。

官方把 `IP-CIDR` / `IP-CIDR6` 定义为匹配 IP 地址范围，把 `SRC-IP-CIDR` 定义为匹配来源 IP 地址范围。附加参数 `src` 仅支持关于目标 IP 的规则，作用是把目标 IP 匹配转为来源 IP 匹配。核对时必须先分清：你以为的连接地址是目的端，还是本机或客户端来源。两者不一致时，规则即使语法正确也不会命中你正在观察的那一侧。

## 按解析与规则类型核对实际地址

先看请求进入匹配时带的是主机名还是字面 IP。若是字面 IP，直接检查它是否落在该行 payload 的范围内，以及地址族是否与规则一致。若是主机名，则目标 IP 规则依赖解析。官方说明：域名开始匹配关于目标 IP 的规则时，mihomo 将触发 DNS 解析来检查域名的目标 IP 是否匹配；可以选择 `no-resolve` 跳过这次解析。因此，带了 `no-resolve` 的行，在尚未获得目标 IP 时不会用解析结果去比较网段。但若更早的匹配已经触发过 DNS，则依旧会匹配到添加了 `no-resolve` 的目标 IP 类规则。判断依据是：本次请求有没有可用的目标 IP，以及该 IP 来自哪一次解析。

接着把实际地址与规则类型对齐。目标侧用 `IP-CIDR`、`IP-CIDR6`、`IP-SUFFIX`、`IP-ASN`、`GEOIP`；来源侧用 `SRC-IP-CIDR`、`SRC-IP-SUFFIX`、`SRC-IP-ASN`、`SRC-GEOIP`。不要用目的端的服务地址去解释 `SRC-IP-CIDR,192.168.1.201/32,DIRECT` 这类来源规则。`IP-SUFFIX` 匹配的是 IP 后缀范围，不能按 `IP-CIDR` 的网段包含关系去核对。若请求为 UDP，而所选代理节点没有 UDP 支持，官方说明会继续向下匹配，看起来也会像 IP 规则不命中。

建议把核对顺序固定为三步：列表中第一条命中的规则是什么；当时用于比较的是域名、目标 IP 还是来源 IP；该 IP 是否落在 payload 范围内。逻辑规则 `AND` / `OR` / `NOT` 会把地址条件与 `NETWORK` 等组合，官方要求注意括号，括号错误时也会表现为 IP 条件从未成立。`SUB-RULE` 同样需要括号，地址可能在子规则里才比较。

## 判断依据与失败时下一步

判断依据：能指出实际参与比较的那一个地址，或能指出从未解析出目标 IP；能指出从顶部起第一条命中规则的类型与策略；能解释该地址为何不在当前 payload 内，或为何根本没轮到 IP 行。

失败时下一步：若第一条命中的是 `DOMAIN`、`GEOSITE` 或 `RULE-SET`，先调整域名规则顺序，而不是改 CIDR。若主机名访问且该行带 `no-resolve`、同时前方也从未解析，则去掉 `no-resolve` 或把需要按目标 IP 比较的行放到仍允许解析的位置后再对照。若 IPv4 规则对 IPv6 字面地址没有反应，补对应地址族的 `IP-CIDR` 或 `IP-CIDR6`。若误加 `src`，去掉后再用目标地址核对。确认地址已落入范围仍不命中时，检查 `MATCH` 是否被提前，以及 UDP 是否因节点能力不足而继续向下。不要在未核对地址族和来源、目标之前扩大网段。
