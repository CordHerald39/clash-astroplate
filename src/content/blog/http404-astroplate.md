从别处复制 Clash 订阅地址时，若末尾或多出来一个符号（空格、引号、斜杠、逗号、换行、多余问号等），客户端实际发出的 URI 已经不是原来那条。服务器只根据收到的请求判断资源，不会自动忽略「看起来像笔误」的字符。MDN 把 404 解释为找不到所请求资源，在浏览器中即 URL 不被识别；把 400 解释为服务器认为存在客户端错误，例如畸形请求语法。多一个符号之后究竟得到哪一种码，要用响应本身判断，不能预先保证一定 404。

## 适用条件

适用于：地址刚复制进客户端，更新失败，且能看到 HTTP 状态码。若完全没有状态码，先当连接未完成，不要解释成「多打了一个字符」。本说明不涉及具体客户端菜单，只根据状态码判断 URI 被改写后的结果。

## 多一个符号后如何用状态码判断

1. 先看是否变成无法识别的 URL。路径或查询被插入额外字符后，服务器找不到对应资源，典型完成态就是 404。判断依据：同一主机下，去掉多余符号后请求变为 200（GET 成功意味着资源已取到并放进响应体），即可认定问题出在 URI 文本，而不是订阅源宕机。
2. 看是否变成畸形请求。多余引号、非法分隔、把两段地址粘成一段，可能让报文在服务器看来语法错误，从而 400。400 与 404 不同：前者是请求写得无法处理，后者是请求被理解了但资源不存在。
3. 看 URI 是否过长。反复粘贴、把说明文字一并复制进地址，可能触发 414（URI 长于服务器愿意解释的长度）。单个符号很少单独导致 414，但「复制时连带大段文本」应当核对总长度。
4. 看是否碰巧指向别的位置。多一个斜杠或改写查询后，若新 URI 仍存在，可能 200，或 301、308 永久换位，或 302、307 临时跳转。这时危险在于：失败日志不明显，取到的却不是原订阅。302 的语义还要求后续仍使用原来的 URI。
5. 排除易混码：401 是未认证，403 是身份已知但拒绝给出资源，405 是方法不被允许。这些都不是「多一个符号」的第一解释。

## 失败时下一步

对照复制源逐字符检查空白与标点，只保留方案、主机、路径和必要查询。修正后若仍 404，改为按路径或资源是否存在排查，不要继续删减正常路径段。若变成 5xx，问题不在多一个符号。记录时保存脱敏 URI 结构与状态码，不要保存完整令牌。
