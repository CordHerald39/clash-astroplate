更换订阅所用域名之后，TLS 失败通常发生在新名字与证书身份、旧重定向链或网关上游尚未对齐的阶段。若握手失败，将没有任何 HTTP 状态码，只能说明新域名上的传输层身份或协议升级没有完成。若已经出现响应，则应把新域名下的 scheme、authority 与状态码对照，区分是永久换址、暂时换址、请求打到不能作答的服务器，还是网关没有从上游拿到合法结果。订阅定位里的查询参数只需保留形如 token=示例 的片段来核对应答，不必把完整定位写成可猜测的绝对地址。

## 适用条件：先判断失败停在哪一层

排查起点是：更换域名后的请求有没有得到标准 HTTP 状态码。没有状态码，问题仍在 TLS 或连接建立，HTTP 五类状态（100–199、200–299、300–399、400–499、500–599）都还用不上。已有状态码时，才能按 RFC 9110 中的定义解释。未列出的码是非标准或自定义响应，不能当作“订阅已生效”或“TLS 已恢复”的证据。

426 Upgrade Required 表示服务器拒绝在当前协议下执行请求，但可能在客户端升级后再接受，并会通过 Upgrade 头指出所需协议。更换域名后若旧连接仍按原协议说话，可能看到该码。判断依据是响应明确要求升级。下一步是改用对端声明的协议再取同一资源，而不是把失败写成证书可以忽略。101 Switching Protocols 是对 Upgrade 的确认，只有在客户端确实发出升级请求后才有意义。

## 用重定向与 421 核对“新域名是不是对的那个权威”

301 Moved Permanently 表示请求资源的 URL 已永久改变，新 URL 在响应中给出。308 Permanent Redirect 语义相近，但跟随时不得改变原方法。302 Found 表示 URI 暂时改变，将来仍应使用原 URI；307 Temporary Redirect 同样是暂时换址，且必须保持原方法。更换订阅域名后，若旧名字返回 301 或 308，应检查 Location 中的主机是否就是你正在改用的新域名，以及下一次握手的证书是否覆盖该名。若 Location 指向又一个不同名字，TLS 会在跟随后再次失败。

421 Misdirected Request 表示请求被导向无法产生响应的服务器，原因可以是服务器未配置去响应请求 URI 中的 scheme 与 authority 组合。这是更换域名后最值得优先对照的客户端错误：新域名在 DNS 或入口上指向了另一套服务，HTTP 层会直接说“我不能为这个权威作答”。判断依据是 421 与新 authority 同时出现。下一步是确认新域名确实配置为该订阅资源的权威名，而不是沿用旧路径硬请求。400 Bad Request 则涵盖畸形语法、分帧错误与欺骗性路由，若新域名被拼进错误的 Host 或请求行，应先纠正请求目标。

200 OK 在 GET 下表示资源已取回；HEAD 只有头。304 Not Modified 表示可以继续用缓存副本。它们只能说明“当前这个权威上的这一次 HTTP 成功”，不能倒推 TLS 失败已经被排除。404 Not Found 表示找不到资源；410 Gone 表示内容已永久删除且无转发地址，客户端应去掉缓存与链接。更换域名后出现 404 或 410，说明 HTTP 已通但资源不在该路径，与“TLS 完全失败”不是同一诊断。

## 失败时的下一步

502 Bad Gateway 表示作为网关处理请求时拿到了无效上游响应。504 Gateway Timeout 表示网关不能在时限内得到响应。更换域名后若入口已换、上游仍指向旧证书或不存在的后端，容易落到这两类。判断依据是：客户端已经完成到入口的 HTTP，但入口对上游不满意。下一步是核对上游是否以新域名的身份提供有效响应，而不是在客户端关闭证书校验。503 Service Unavailable 表示尚未准备好处理请求，常见于维护或过载，属暂时条件；若存在 Retry-After，应按其中估计时间再试，且暂时响应通常不应缓存。

408 Request Timeout 可用于空闲连接，部分服务器即使未收到新请求也会用它关闭连接。更换域名后若复用了旧连接，可能先看到 408，下一步应针对新域名建立新连接。425 Too Early 拒绝可能被重放的请求，不适合在域名切换的瞬间用同一条旧请求密集重放。429 Too Many Requests 是速率限制，应降低频率。500 Internal Server Error 只说明服务器遇到无法处理的情况，是通用 5xx，不能单独指向 TLS。505 则是 HTTP 版本不被支持。

收敛条件是：新域名上能够稳定出现针对该 authority 的成功类响应，或可解释的 304，或方法保持规则正确的 307/308 跟随且跟随目标仍在证书覆盖范围内。若始终没有状态码，或反复出现 421 与 502/504，应把新域名的权威名、重定向目标和网关上游分开查，而不是把订阅参数改来改去当作 TLS 修复。
