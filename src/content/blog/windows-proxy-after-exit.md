只有启动 Clash Verge Rev 才能联网，退出后浏览器立刻失败，先检查 Windows 是否仍启用手动代理。开发者 FAQ 说明，断电、蓝屏或其他异常退出可能让系统代理没有正确关闭。程序已经不监听，系统却继续把请求交给旧地址，就会出现这种症状。

## 先确认是不是这一类问题

记录退出前后同一浏览器、同一目标的结果，查看 Windows 设置中的代理地址与端口。正常退出和只关闭客户端窗口也不同，窗口关闭后程序可能仍留在托盘。确认程序是否真正退出，再解释网络现象。

如果网络设备本身断线，或没有启用手动代理，就不要把所有失败都归为残留代理。这里的排查仅针对自己管理的设备；组织要求的代理设置需由管理员确认，不能直接清除。

## 使用系统设置恢复原有访问路径

开发者给出的入口是 Windows 设置 → 网络和 Internet → 代理 → 手动设置代理，关闭“使用代理服务器”。操作前记录原地址与端口，便于判断是否属于当前客户端。无需为了清除代理卸载网卡、重装客户端或删除订阅。

关闭后重新建立浏览器连接，访问原目标。若恢复，说明该次失败与残留手动代理有关；这不能证明目标在所有网络中可达，也不能证明订阅是否有效。应用自行设置的代理可能还需要在应用内检查。

## 再启动客户端时要核对实际值

再次启动当前安装位置的程序，确认内核正在运行、显示的代理端口与系统设置一致，再开启系统代理并发起同一请求。不要把旧教程中的端口硬写回系统，也不要把控制面板端口当转发端口。

若正常退出也重复留下代理，记录客户端版本、退出方式与退出前后设置。多客户端同时运行也可能轮流修改系统代理，可逐个正常退出并核对自己的状态。一次只保留一个准备接管流量的实例，避免用反复重启掩盖地址被覆盖。

仍未恢复时，按[连接检查](/blog/connection-check/)区分网络、接管与上游连接问题。资料：[Clash Verge Rev Windows FAQ 的“不打开 Clash 无法使用网络”](https://www.clashverge.dev/faq/windows.html)。本文为文档整理，没有修改读者电脑设置或进行联网亲测。
